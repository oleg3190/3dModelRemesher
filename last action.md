### 1. Сначала — `--quality` пресет

Это правильный следующий шаг, потому что он:

- фиксирует доказанный выигрыш;
- убирает магию из переменных окружения;
- сохраняет текущий `default OFF` и бит-идентичный baseline;
- позволяет пользователям осознанно включать ремонт входа;
- не ломает существующие пайплайны, которые ожидают старое поведение.

То есть это безопасная продукт-фиксация уже достигнутого результата.

Пример поведения:

```bash
qremesh input.glb -o out.obj --target 10000 --quality
```

эквивалентно проверенному режиму:

```text
QREMESH_WELD_SCALE=500
QREMESH_NM_KEEP_BEST=1
QREMESH_DROP_DEBRIS=1
```

Но лучше, чтобы это были не просто выставленные `env`, а нормальные внутренние опции, которые логируются:

```text
[preset] quality=on weld_scale=500 nm_keep_best=on drop_debris=on single_shell=off
```

---

### 2. `keep-best-2` в дефолт — да, но осторожно и отдельно

`keep-best-2` выглядит как лучший кандидат в дефолт, потому что:

- он не трогает чистый single-manifold вход;
- на грязных входах даёт сильный рост качества;
- он решает фундаментальную проблему, а не маскирует её.

Но это всё равно **изменение топологического поведения** для неидеального входа. Поэтому я бы не включал его молча в общий дефолт одним движением.

Правильнее сделать так:

```text
default:
    nm_policy = keep-best-2
```

но с возможностью отключить:

```bash
--nm-policy=off
--nm-policy=keep-all
--nm-policy=keep-best
```

или короче:

```bash
--no-nm-repair
```

И обязательно логировать:

```text
[input-repair] nonmanifold_edges=124 keep_best_applied=1 removed_nm_branches=17
```

## Что я бы не делал

### Не включал бы полный `--quality` в дефолт

Полный quality mode включает:

```text
weld
keep-best
debris-drop
```

`weld` и `drop_debris` потенциально меняют геометрию и могут удалить маленькие, но реальные части. Это уже более агрессивный ремонт.

Поэтому:

```text
keep-best-2 → можно рассматривать как дефолт;
weld + debris → пока только через --quality или отдельный явный ремонтный профиль.
```

## Предлагаемое решение по шагам

### Шаг A. Сейчас: добавить `--quality`

Сделать явный пресет:

```bash
--quality
```

который включает:

```text
weld_scale = 500
nm_keep_best = on
drop_debris = on
single_shell = off
```

Важно:

- `--quality=off` должен явно возвращать старый режим;
- CLI должен иметь приоритет над `env`;
- без флага поведение должно быть бит-идентично текущему `OFF`;
- в логе должен печататься активный пресет;
- все существующие `env` остаются рабочими, но помечаются как low-level override.

Можно сделать так:

```bash
--quality=on|off|full|safe
```

где:

```text
off   — старый дефолт
safe  — только keep-best-2, если захотите выделить безопасный ремонт
full  — weld + keep-best + debris, текущий доказанный quality-mode
```

Но если не хочется усложнять, начните с простого:

```bash
--quality
```

и всё.

---

### Шаг B. Отдельный ADR на `keep-best-2` default

Не смешивайте это с `--quality`.

Сделайте отдельную запись, например:

```text
S41 · keep-best-2 как дефолт для неидеального входа
```

Гипотеза:

> Если вход содержит non-manifold рёбра, политика `keep-best-2` улучшает качество выходной сетки и не ухудшает чистые манифолдные входы, поэтому может быть включена по умолчанию как автоматический ремонт.

Критерии принятия:

1. Чистые манифолдные входы:
   ```text
   output bit-identical или метрики без изменений
   ```

2. Грязные входы:
   ```text
   median SJ не хуже, лучше — лучше
   non-manifold уменьшается или исчезает
   components не теряют реальные лобсты без явного single-shell
   ```

3. Self-intersecting / multi-shell модели:
   ```text
   компоненты не удаляются только из-за размера
   ```

4. Hausdorff:
   ```text
   без деградации выше заранее оговоренного порога
   ```

5. Детерминизм:
   ```text
   3 прогона дают идентичный результат
   ```

6. Время:
   ```text
   приемлемый оверхед, например < +10–20%
   ```

Если эти критерии выполняются — можно поднимать.

## Как я бы сформулировал политику дефолтов

Идеальный конечный вариант:

```text
По умолчанию:
    - чистый вход не трогаем;
    - при наличии non-manifold применяем keep-best-2;
    - weld и debris-drop только через --quality или явные флаги;
    - удаление компонент только при явном --single-shell / --drop-small-shells.
```

То есть:

```text
default = safe topology repair
--quality = aggressive quality repair
```

Это разделяет два уровня:

| Режим | Что делает | Риск |
|---|---|---|
| `default` | только безопасный `keep-best-2` при наличии NM | минимальный |
| `--quality` | weld + keep-best + debris | выше, но явный |
| `--single-shell` | ожидает/форсит одну оболочку | может резать реальные лобсты |

## Что обязательно должно быть в `--quality`

### 1. Явный лог эффективных настроек

Например:

```text
[config] quality=full
[config] weld_scale=500
[config] nm_keep_best=on
[config] drop_debris=on
[config] single_shell=off
```

Это важно для воспроизводимости.

---

### 2. Приоритет настроек

Рекомендую такой порядок:

```text
явный CLI флаг > --quality preset > env > built-in default
```

Например:

```bash
QREMESH_NM_KEEP_BEST=0 qremesh input.glb --quality
```

должен всё равно включить `keep-best`, потому что пользователь явно запросил `--quality`.

Но если нужно тонкое управление:

```bash
qremesh input.glb --quality --no-weld
```

или:

```bash
qremesh input.glb --quality --drop-debris=off
```

если решите добавить индивидуальные переопределения.

---

### 3. Не менять цель по полигонам

`--quality` не должен сам менять `target`.

Он должен улучшать вход и топологию, но бюджет полигонов остаётся пользовательским параметром.

То есть:

```bash
--target 10000 --quality
```

означает:

```text
цель 10000 квадов, но с улучшенным входом
```

а не:

```text
автоматически поднять цель до 15000
```

---

## Что обязательно должно быть в default-промоушене `keep-best-2`

### 1. Opt-out

Если дефолт меняется, нужен явный выход:

```bash
--nm-policy=off
```

или:

```bash
--no-nm-repair
```

---

### 2. Телеметрия/счётчики

Желательно печатать:

```text
[input] nonmanifold_edges=N
[nm-repair] keep_best_applied=1
[nm-repair] resolved_edges=N
[nm-repair] skipped=0
```

Если ничего не применялось:

```text
[nm-repair] keep_best_applied=0 reason=no_nonmanifold_edges
```

Это сразу объясняет, почему чистый вход не изменился.

---

### 3. Защита от удаления реальной геометрии

`components=1` не должен быть универсальным требованием.

Нужен отдельный режим:

```bash
--single-shell
```

или:

```bash
--components-policy=keep|largest|error
```

По умолчанию:

```text
components-policy = keep
```

То есть лишние компоненты допускаются, если они являются реальными частями модели.

## Регрессия для принятия `keep-best-2` в дефолт

Я бы гонял не только базовые таргеты, а отдельный набор моделей.

### Обязательные классы тестов

1. **Чистый watertight manifold**
   - ожидаем: бит-идентичность или нулевое изменение метрик.

2. **Чистый открытый, но манифолдный**
   - ожидаем: без изменений.

3. **Грязный non-manifold**
   - ожидаем: улучшение SJ, уменьшение проблем.

4. **Модель с реальными несколькими оболочками**
   - ожидаем: компоненты сохраняются.

5. **Модель с мелкими, но важными лобстами**
   - ожидаем: не удаляются без явного `--single-shell`.

6. **Self-intersecting AI-модель**
   - ожидаем: не форсируем одну компоненту.

7. **Плотная модель около порога QEM/proxy**
   - ожидаем: качество не падает из-за прокси.

8. **Модель с near-coincident вершинами**
   - ожидаем: поведение стабильно, но для дефолта без `weld` не должно быть агрессивной сварки.

## Критерии go/no-go для дефолта

### Можно поднимать `keep-best-2` в дефолт, если:

```text
1. Чистые входы не меняются.
2. На грязных входах median SJ растёт или не падает.
3. Нет случаев молчаливого удаления реальных компонент.
4. Нет деградации Hausdorff выше согласованного порога.
5. Детерминизм подтверждён.
6. Есть явный --nm-policy=off.
7. В логе видно, что именно было отремонтировано.
```

### Не поднимать, если:

```text
- есть хотя бы один класс моделей, где теряется нужная геометрия;
- меняется поведение на манифолдном входе;
- нельзя объяснить пользователю, что дефолт делает ремонт;
- нет быстрого и понятного opt-out.
```

# ГЛАВНЫЕ ПРАВИЛА РАБОТЫ В MCP (СТРОГО К ИСПОЛНЕНИЮ)

1. **АТОМАРНОСТЬ (ATOMIC EXECUTION):** Разбей сборку на логические атомарные шаги (последовательные вызовы MCP-инструментов с компактными, самодостаточными блоками Python-кода).
2. **ПОЛНЫЙ ЗАПРЕТ НА ТЕКСТ (ZERO CHATTER):** Между вызовами MCP-инструментов КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО выводить любой текст, комментарии, рассуждения, markdown-блоки или объяснения. Генерируй исключительно tool calls.
3. **БЕЗ УТОЧНЕНИЙ:** Собирай модель СТРОГО по предоставленному списку и референсу. Не задавай вопросов. Входное ТЗ — это Single Source of Truth.
4. **ЖЕСТКАЯ ИЗОЛЯЦИЯ СРЕДЫ (MULTI-AGENT SAFETY):** Ты работаешь в одном инстансе Blender с другими агентами. 
   - В первом шаге сгенерируй короткий уникальный префикс сессии: `AGENT_ID = f"Ag_{uuid.uuid4().hex[:6]}"`.
   - Создай собственную независимую сцену `scene = bpy.data.scenes.new(f"{AGENT_ID}_Scene")` и сделай её активной (`bpy.context.window.scene = scene`).
   - Создай корневую коллекцию `f"{AGENT_ID}_Root"` и привяжи её ТОЛЬКО к своей сцене.
   - КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО удалять, скрывать или изменять чужие сцены, коллекции, меши и материалы (`bpy.ops.wm.read_factory_settings` и глобальная очистка `bpy.data.objects` под запретом!).
5. **ФИНАЛЬНЫЙ СТАТУС:** Когда все шаги отработали и файлы экспортированы, выведи в чат ТОЛЬКО одну фразу без кавычек и форматирования: Модель готова, проверяйте.

# ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ (API, ТОПОЛОГИЯ, ПУТИ)

## 1. УПРАВЛЕНИЕ ПУТЯМИ (Pipeline & I/O)
- Вычисляй базовую директорию безопасно: `BASE_DIR = bpy.path.abspath("//") if bpy.data.is_saved else os.getcwd()`.
- В первом шаге гарантируй создание папок:
  `PREFABS_DIR = os.path.join(BASE_DIR, "prefabs")`
  `PROGRESS_DIR = os.path.join(BASE_DIR, "input", "progress")`
  `os.makedirs(PREFABS_DIR, exist_ok=True)`
  `os.makedirs(PROGRESS_DIR, exist_ok=True)`
- Все промежуточные рендеры сохраняй в `PROGRESS_DIR` с префиксом `{AGENT_ID}_stepN.png`.
- Финальные ассеты (`.fbx`, `.glb` или `.blend`) сохраняй строго в `PREFABS_DIR`.
- Все создаваемые Data-блоки (Meshes, Objects, Materials, Collections) обязаны начинаться с префикса `{AGENT_ID}_`.

## 2. БЕЗОПАСНЫЙ BLENDER API (Защита от падений контекста MCP)
- **Приоритет Data API и `bmesh`:** При вызове через MCP UI-контекст `3D View` часто недоступен (`poll() failed`). Своди использование `bpy.ops` к минимуму!
- Создавай и модифицируй геометрию преимущественно через модуль `bmesh` (`bmesh.new()`, `bmesh.ops.*`, `bm.to_mesh(mesh)`), а объекты — через `bpy.data.meshes.new()` и `bpy.data.objects.new()`.
- Если оператор `bpy.ops` неизбежен (например, для UV или экспорта), предварительно явно задавай активный объект и выделение в своей сцене:
  ```python
  bpy.ops.object.select_all(action='DESELECT')
  obj.select_set(True)
  bpy.context.view_layer.objects.active = obj

    Для промежуточных скриншотов НЕ используй bpy.ops.render.opengl() (он падает без активного 3D-окна). Создай в своей сцене временную камеру (Изометрия / 3/4 вид, направленную на центр модели), настрой scene.render.engine = 'BLENDER_EEVEE_NEXT' (или 'BLENDER_EEVEE' / 'WORKBENCH'), пропиши scene.render.filepath и вызывай безотказный bpy.ops.render.render(write_still=True, scene=scene.name). Перед финальным экспортом удали временную камеру и свет.

3. ФИЗИЧЕСКАЯ КОРРЕКТНОСТЬ, ТРАНСФОРМАЦИИ И PIVOT

    Единицы измерения: метрические (1 unit = 1 метр). Строго соблюдай реальные физические габариты и пропорции элементов.

    ПРАВИЛО PIVOT POINT (КРИТИЧНО):

        У финального корневого объекта (или единого меша) Origin обязан находиться строго в основании по центру: X = 0, Y = 0, Z = 0 (нижняя точка геометрии лежит на плоскости Z = 0, модель не проваливается под землю и не висит в воздухе).

        ВНИМАНИЕ: Не применяй location=True к объектам, у которых Origin должен быть смещен от мирового нуля! Вместо этого смещай саму сетку через mesh.transform(Matrix.Translation(...)) или собирай модель сразу относительно (0, 0, 0) и применяй bpy.ops.object.transform_apply(location=False, rotation=True, scale=True), чтобы Scale строго равнялся (1.0, 1.0, 1.0), а Rotation — (0.0, 0.0, 0.0).

    Проверяй направление нормалей: после любых булевых и bmesh-операций вызывай bmesh.ops.recalculate_face_normals(bm, faces=bm.faces).

4. ТОПОЛОГИЯ И HARD-SURFACE СТАНДАРТЫ

    Чистая сетка из квадов (quads) и треугольников. Никаких висячих вершин (loose geometry), дублей вершин (bmesh.ops.remove_doubles(bm, verts=bm.verts, dist=0.0001)) и non-manifold ребер.

    Для булевых вычитаний используй модификатор BOOLEAN с солвером 'EXACT' (или 'FAST', если геометрия перекрывается без копланарных граней), сразу применяй его и очищай сетку от артефактов.

    На всех жестких гранях добавляй фаски через модификатор BEVEL (width по масштабу детали, segments=2..3, limit_method='ANGLE', angle_limit=math.radians(30), harden_normals=True или в связке с WEIGHTED_NORMAL).

5. ШЕЙДИНГ, МАТЕРИАЛЫ И UV

    Сглаживание (совместимость с Blender 4.0+): НЕ используй устаревший mesh.use_auto_smooth! Включай сглаживание полигонов через Data API:mesh.polygons.foreach_set("use_smooth", [True] * len(mesh.polygons))
    и добавляй модификатор WEIGHTED_NORMAL с параметром keep_sharp=True в конец стека (перед триангуляцией).

    PBR-Материалы: Создавай материалы с use_nodes = True на базе Principled BSDF. Задавай физически корректные Base Color, Roughness и Metallic. Назначай их на соответствующие полигоны через material_index.

    UV-развертка: Выполняй bpy.ops.uv.smart_project(angle_limit=math.radians(66), island_margin=0.02) в EDIT режиме на финальном меше, чтобы избежать наложений (overlapping UVs).

# ЧЕКЛИСТ ОШИБОК ИЗ ПРАКТИКИ (РАНЕЕ ДОПУЩЕНЫ — НЕ ПОВТОРЯТЬ)

Каждый пункт — реальный баг из прошлых итераций. Перед финальным рендером пройди по списку.

## A. Силуэт, «торцы», координаты
1. **ЗАПРЕТ случайного джиттера по вершинам.** `random.uniform(±0.05)` при шаге ячейки 2–3 см (тонкая ось стены/плиты) даёт заломы и «иглы» по кромкам — сетка складывается гармошкой. Если повреждение силуэта вообще нужно — только плавная ДЕТЕРМИНИРОВАННАЯ функция координаты ВДОЛЬ кромки (sin/шум от координаты кромки), смещение строго ВНУТРЬ габарита, одинаковое для всех вершин одного поперечного сечения. Если в ТЗ «торцы прямые» — любое смещение силуэта запрещено, торец = грань правильного параллелепипеда.
2. **Перед любым изменением вершин применяй location:** `transform_apply(location=True)`, иначе локальные координаты сдвинуты относительно мира и условия вида `abs(z - H) < 0.02` НЕ срабатывают (mesh живёт от −H/2 до +H/2), а `abs(z) < 0.02` захватывает середину грани — джиттер уходит не на ту кромку (был баг: повредили срединное кольцо вместо низа).
3. **Порядок применения трансформаций:** сначала scale, ПОТОМ rotation (поворот идёт вокруг локального origin = центра объекта), ПОТОМ location. Обратный порядок (`location` применён → `transform_apply(rotation=True)`) вращает меш вокруг мирового начала — деталь улетает (был баг: слив уехал внутрь стены и стал невидим).

## B. Булевы
4. **После КАЖДОГО boolean — автопроверка:** сравни `dimensions` до/после; если любая ось уменьшилась более чем на 50% — меш уничтожен, откатывай и пробуй другой солвер/чини сетку. Пример:
   ```python
   prev = tuple(target.dimensions); apply_mod(target, mod.name)
   if any(p > 0.1 and n < p*0.5 for p, n in zip(prev, tuple(target.dimensions))):
       raise RuntimeError(f"boolean destroyed mesh: {prev} -> {tuple(target.dimensions)}")
   ```
5. **Солверы:** в Blender 4/5 enum = `('FLOAT', 'EXACT', 'MANIFOLD')` — `'FAST'` больше нет (TypeError). EXACT на самопересекающейся/рваной сетке рвал меш до 3 граней; для простых вырезов по чистому кубу бери FLOAT, после любого джиттера сетку сначала «лечи» (remove_doubles + recalc normals).
6. **Не оставляй каттеры** в сцене и не делай вырезы там, где грань каттера становится копланарной стенке объекта (см. C.7).

## C. Копланарность — главный источник чёрных артефактов
7. **ЗАПРЕТ совпадающих плоскостей между объектами:** торец рельса в плоскости торца стойки, стенка рамы в плоскости стенки проёма, край стекла в плоскости импоста, грань заплатки в плоскости рельса, верх стойки в плоскости плиты. Результат — z-fighting и чёрные щели в углах. Правило: **перекрытие объёмов 2–5 мм** (нижний элемент топится внутрь верхнего на ≥2 мм), либо честный зазор ≥2 мм. Концы «длинных» рельсов, накрывающих стойку, сдвигай на 2 мм ПЕРЕД торцом стойки.
8. **Стыки перил — без заплаток-кубов** (кубы-заглушки дают копланарные грани и выглядят как заплатка): верхний рельс делается ДЛИННЕЕ и перекрывает стык; нижний сегмент заканчивается точно под его нижней гранью; вертикальная стойка заканчивается ВНУТРИ тела горизонтального рельса. Торец наклонного рельса проверяй: верхний угол сечения `(t/2)*(|sinθ|+|cosθ|)` должен быть НИЖЕ верха принимающего рельса, иначе угол торчит сверху.
9. **Окна:** одно стекло на весь проём (не 2–3 панели встык — их грани копланарны), края стекла утоплены в раму/импосты на 10 мм; рама «заряжена» в стену на 10 мм, не встык с торцом проёма.
10. **Стойки/балясины:** верх = линия рельса + 2 см (внутрь сечения на 5–8 мм), низ топится в плиту/ступень на 10–15 мм — НЕ встык (встык даёт копланарный квадрат-артефакт сверху/снизу стойки).

## D. Расчёт линий: стойки и рельсы — одна функция
11. **Сегмент рельса и стойки считай из ОДНОЙ линии.** Запрещено строить скат из «усечённых» кусковых значений (clamp по концам `if y<=0: return const`): уклон рельса менялся с 0.607 на 0.515 и стойки «не дотягивались» до рельса на 15 см. Для марша: `z = z0 + (rise/run)*y` сквозь обе точки, уклон параллелен ступеням.
12. **Обязательная программная проверка стыка** после сборки (не на глаз):
    ```python
    ok, loc, *_ = rail.closest_point_on_mesh(bar_top_center)
    assert (bar_top_center - loc).length < 0.01, f"{bar.name} не достаёт до рельса"
    ```
    Прогони по ВСЕМ стойкам; max расстояние должен быть 0.005–0.008 (точка внутри рельса).

## E. Верификация: не верь глазам в одиночку
13. **Параллакс = ложные зазоры.** Три параллельных ограждения/элемента на разных X дают на рендере «висящие» стойки — глаз цепляет стойку одного элемента за рельс другого. Порядок действий перед правкой: (1) **изолируй** узел (hide всех чужих объектов) и сними крупный план; (2) проверь **численно** (closest_point_on_mesh, world_to_camera_view — верх стойки должен попадать в экранную полосу рельса); (3) лучевой скан по столбцам кадра на паттерн `Rail_* → sky(≥8px) → Bar_*` — ищи только совпадения «свой рельс ↔ своя стойка».
14. **Не доверяй одной проверке:** «точка внутри бокса» ≠ отсутствие артефакта (копланарность, z-fighting). Любая численная победа подтверждается финальным рендером ИЗОЛИРОВАННОГО узла (крупный план), а не общим кадром.

## F. Сцена, рендер, бюджет
15. **Настройки сцены переживают удаление объектов:** `view_transform`/`exposure`/`engine` выставляй ЯВНО каждый запуск (переживший `Standard` вместо `AgX` дал пересвет «в белое»). Каждый новый бамп-рендер — с теми же явными настройками.
16. **Считай полигонаж после каждого шага** (`mesh.calc_loop_triangles()` → сумма faces/tris) и сверяй с лимитом ТЗ до финального экспорта; бюджет держи с запасом (место на Bevel/детали).
17. **Трансформации финального меша:** Scale = (1,1,1), Rotation = (0,0,0), основание на Z = 0, pivot в (0,0,0) — проверяй ПЕРЕД экспортом (п. 3 основного раздела).

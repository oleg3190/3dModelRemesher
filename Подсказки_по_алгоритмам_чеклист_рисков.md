# Подсказки по алгоритмам QuadRemesher для разработки собственного пакета
## Чеклист рисков: где мы можем ошибиться

> Основа — маркеры, найденные в бинарнике (`xremeshlib.dll`): слаги параметров, RTTI-классы, строки логов.
> Каждый пункт: **что делал оригинал** (по следам) → **наша типичная ошибка** → **как проверить**.
> Пометки: ⬛ = подтверждено строками, ⚀ = разумное предположение.

---

## 0. Общие (до всех стадий)

### 0.1. Чистый вход решает всё
⬛ В логах: `Failed while loading and preparing the mesh!`, коды `BadInput / OutOfMemory / NonManifold`,
`clean-make-manifold-mesh`, `Marking holes for elimination`, `select-degenerated-*`, weld.

**Наша ошибка:** начинать умный алгоритм на «грязном» меше — незашитые дыры, инвернутые нормали,
дубликаты вершин, нулевые треугольники, несогласованная ориентация граней.
**Что будет:** поле направлений не сходится, трассировка утекает в дырки, «успех» невозможно объяснить.
**Проверка:** пропустить через Prep набор заведомо битых мешей (fixtures `nonmanifold_broken`) —
движок обязан дать предсказуемый отказ, а не молча мусор.

### 0.2. Детерминизм
⬛ Слаги `au-dbg-savesteps`, `last algo total time`, повторяемые стадии.
**Наша ошибка:** многопоточность с гонками, `std::unordered_map` в порядке обхода, rand() без seed.
**Проверка:** два прогона → бит-в-бит иначе = баг. Зафиксировать seed и порядок обхода.

### 0.3. Между стадиями — снимки
⬛ Есть `au-dbg-savesteps`, Debug-вывод в `.obj` (в QRemeshify — так же, `Use Cache`).
**Наша ошибка:** монолитная функция «вход→выход», отладка методом тыка.
**Проверка:** каждый этап сериализуется в OBJ; можно визуально найти стадию, где появился дефект.

## 1. Prep: топология и шарпы

### 1.1. Шарпы — не только угол
⬛ `AutoDetectHardEdges_Angle`, `crease-angle-param`, `auto-detect-hard-edges`,
`split-groups-by-normals-angle`, плюс копирование ручных `sharp`/`crease` из Blender.
**Наша ошибка:** детект только по углу между нормалями. Оригинал, вероятно ⚀, объединяет:
угол + ручные флаги + UV-seams + границы материалов/полигон-групп.
**Проверка:** модель с идеальными90°-рёбрами без ручных шарпов и с ручными шарпами при плоской поверхности —
обе должны дать одинаково чистую границу.

### 1.2. Дырки: чинить или уважать
⬛ `Input holes: %d`, `Marking holes for elimination` + отдельно `keep_input_border` (в ТЗ).
**Наша ошибка:** зашивать **все** дыры — в открытой модели (полость рта, труба) это ломает смысл,
не зашивать **никогда** — трассировка утекает.
**Проверка:** у модели с 1 «намеренной» и 1 «случайной» дыркой — первая остаётся, вторая закрывается.

### 1.3. Генус и полюса
⬛ `GENUS REDUCTION CASE`, `select-poles`, `select-loops-from-poles`, `GridPole`,
`INTVARFLAG_GENUS_REDUCTION_*`.
**Наша ошибка:** не обрабатывать полюса (вершины valence ≠ 4) — они **неизбежны** там, где топология
не даёт чистой valence-4 (тор, дырки, сингулярности поля). Оригинал явно выделяет их как объект
для управления и для выбора пользователем.
**Проверка:** на торе/бутылке посчитать долю valence-3/5 после релаксации — если >15% и они стоят
в неудобных местах, управление полюсами не работает.

## 2. Propo: поле размера

### 2.1. Плотность ≠ равномерность
⬛ `VarDensityRatio`, `CurvatureAdaptivness`, `as-density`, `TargetEdgeLength`.
**Наша ошибка:** либо полностью равномерная сетка (теряется детализация),
либо чисто кривизнная (на шуме скульпта сетка «пляшет»).
**Проверка:** модель с гладким участком + одним острым изгибом: плотность должна плавно
возрастать к изгибу и быть ровной на гладком.

### 2.2. Защита от шума кривизны — до поля размера
⬛ `Denoise`, `DenoiseStrength`, `denoising-factor`, `rtp-curvmode-protectdenoise`, `PROTECT_DENOISE`.
**Наша ошибка:** считать кривизну по «сырому» мешу → поле плотности наследует шум скульпта →
сетка рябит. Оригинал имеет отдельную операцию денойза **и** режим «protect denoise»,
когда пользовательское направление/размер защищается от сглаживания.
**Проверка:** меш с наложенным шумом 0.1% bbox — распределение длин рёбер должно остаться плавным.

### 2.3. Конфликт кривых и плотности — отдельная стадия
⬛ Маркер фазы `0c-AfterDensifyAroundIncompat` («уплотнение вокруг несовместимых») + `densify-max-iter-count`,
`densify-max-vertex-count`.
**Наша ошибка:** считать, что кривая и поле размера всегда согласованы. Они конфликтуют постоянно
(широкая кривая на мелкой сетке). Оригинал — **специальная фаза локального уплотнения** вокруг таких мест,
с явными потолками итераций/вершин, чтобы не взорвать память.
**Проверка:** широкий edge-loop через зону мелкой плотности — не должно ни «ступенек»,
ни взрыва числа полигонов (`densify-max-*` обязан срабатывать).

### 2.4. Штраф за «ступеньки»
⬛ `au-penal-stair`.
**Наша ошибка:** при построении размерной сетки получать ступенчатый переход плотности
(патч из 5×5 и рядом патч из 10×10 → шов волной). Оригинал **штрафует** такие переходы прямо в критерии.
**Проверка:** визуально шов между зонами разной плотности — ступенек быть не должно.

## 3. Field: поле направлений

### 3.1. Две разные схемы релаксации — не одна
⬛ Слаги `grelaxalgo-HarmoDirGrid3x3` и `grelaxalgo-LaplaceWithEdgLen`.
**Наша ошибка:** взять одну «простую» Лапласову сгладку и считать, что годится для всех зон.
Судя по именам: гармоническая схема на окне 3×3 — для方向 данных (угол на окружности, удвоение угла),
Лаплас по длинам рёбер — для геометрии. Скорее всего ⚀ они применяются **в разные моменты**:
углы поля — HarmoDir, положения вершин — LaplaceWithEdgLen.
**Проверка:** на цилиндре поле должно быть без «вихрей»; на плоскости — без искажений к краям.

### 3.2. Сингулярности — не прятать, а разрешать
⬛ `select-poles`, `GridPole`, `select-loops-from-poles`.
**Наша ошибка:** пытаться сделать поле везде непрерывным — на сфере это невозможно
(теорема Хопфа–Доле: обязательно есть сингулярности). Или игнорировать их — тогда сборка квадов
рождает каскад плохих полигонов вокруг.
**Проверка:** сфера/голова — сингулярности должны стоять в «спокойных» местах (обычно 4 шт. на сфере,
valence-3), а не посреди лица.

### 3.3. Поле обязано слушать кривые и шарпы жёстче, чем кривизну
⬛ `rtp-curvmode-{create,correct,move}`, `rtp-curvtype-*`, `au-keep-exist-seams`.
**Наша ошибка:** относиться к feature-кривым как к мягкой рекомендации — релаксация их «съест».
**Проверка:** замкнутый edge-loop-контур на плоском участке — после релаксации поля
направление вдоль контура должно сохраниться.

### 3.4. Симметрия — поля, а не только вершин
⬛ `MXMeshSymmetryCache`, `au-dbg-newfulltoposym`, `sym-spine-color`, `upd-sym-from-edge`,
`local-sym-flag`, `resym-cmd`, `mirror-merge-exact`.
**Наша ошибка (типичная):** посчитать симметрию в конце — «построить и зеркнуть».
Но если поле строилось асимметрично, сборка квадов разойдётся, и merge-итог будет рваным.
Оригинал: симметричное состояние кэшируется и поддерживается **на всём протяжении**
(`newfulltoposym`, `resym-cmd` = пересобрать симметрию), включая поле.
Ещё нюанс: `sym-spine-color` — ⚀ поддержка «позвоночной» (spine) симметрии, не только XYZ-зеркала.
**Проверка:** асимметричный шум слева — справа он не должен появиться; левая/правая половины
после merge — бит-в-бит зеркальны.

### 3.5. Две фазы симметрии: половина и merge
⬛ `mirror-return-half`, `mirror-source-{left,right,positive,negative}`, `mirror-merge-exact`,
`resym`, `mirror-merge-cmd`.
**Наша ошибка:** обрабатывать весь меш сразу (вдвое дороже и возможно несовпадение половин)
**или** зеркалить без точного merge tolerance → щель/дубль по центру.
**Проверка:** `mirror-merge-exact` на осевой вершине — ровно одна вершина на шве, без зеркальных дублей.

## 4. Trace + Build: трассировка и сборка квадов

### 4.1. Отбраковка — обязательная ветка
⬛ `Abort Edges From InputMesh`, `Abort Edges With Quad`, `Aborted Edges…`.
**Наша ошибка:** считать, что все цепочки встанут в квады. Оригинал явно **отбраковывает**
некорректные рёбра (и отдельно — те, что конфликтуют с уже вставленными квадами)
и отправляет их в резерв (N-угольники/триангуляция).
**Проверка:** считать `#Quad/(#Quad+#Tri+#NGon)` — при ≥95% квадов отбраковка работает;
если 100% на сложной модели — значит отбракованные тихо выкидываются с потерей формы.

### 4.2. N-угольники — не враг
⬛ `rpn-ngon-limit`, `allow_ngons` (в ТЗ), статистика `#NGon`.
**Наша ошибка:** фанатичное «только квады» → бесконечные split/collapse, полисы, дегенераты.
Оригинал допускает N-угольники (с лимитом) в проблемных местах — это **давление клапана**.
**Проверка:** на модели с полисами — при `ngon-limit=8` результат стабильнее, чем при `=4`.

### 4.3. Цепочки не встали → уплотнить и повторить, а не сдаться
⬛ Фазы `0b`/`0c` + `densify-max-iter-count`.
**Наша ошибка:** один проход «собрал что вышло». Оригинал ⚀ имеет цикл:
найти несовместимость → уплотнить вокруг → повторить (с потолком итераций).
**Проверка:** спиральные формы (из жалоб на QRemeshify — у него здесь слабое место!)
должны улучшаться от повторных итераций, а не ухудшаться.

### 4.4. Точное число квадов — распределить, а не «примерно»
⬛ `ExactQuadCount`, `auto-retopo-num-quad`, `auto-retopo-use-numquad-subDivCoef`, `Retopo_%dquad`.
**Наша ошибка:** приблизить число квадов грубо (через размер ячейки). Оригинал при заданном
`numquad` ⚀ распределяет квады по патчам пропорционально и добирает split/collapse'ом.
**Проверка:** `target=5000` → фактически 5000±2% на любом из fixtures.

### 4.5. Существующие швы и UV уважать
⬛ `au-keep-exist-seams`, `delete-UVs-keep-seams`, `select-uv-seams`, `split-groups-by-UV-island`,
`analyse-uvtopo`, `selext-loop-uvtopo`.
**Наша ошибка:** игнорировать UV-швы пользователя → ретопология ломает готовую развёртку.
**Проверка:** меш с UV-островами — после ретопо швы не «разъезжаются» (при включённой опции).

## 5. Opt: оптимизация

### 5.1. Flip/collapse — только с проверками
⬛ `flip-edges`, `collapse-edges`, строки Triangle: `Edge flip results in left…`,
`Edge unflip results in left…`.
**Наша ошибка:** flip по критерию «стало ровнее», без проверки: не нарушено ли поле направлений,
не задет ли шарп/граница/кривая, не вырожден ли треугольник. Результат — «масляные» пятна
на границе патчей.
**Проверка:** статистика flip'ов в зоне шарпа = 0 при включённом `follow_sharp`.

### 5.2. Проекция на поверхность — с потолком
⬛ В ТЗ `max_deviation`; в оригинале метрики `Shortest edge / Longest edge / aspect ratio`.
**Наша ошибка:** безжалостная проекция каждой вершины → сетка «впекается» в шум,
или наоборот — проекция отключена → форма уплывает.
**Проверка:** всегда логировать max/avg deviation; отклонение выше порога = ошибка, а не предупреждение.

### 5.3. Порядок операций: топология → затем геометрия
**Наша ошибка:** чередовать flip/collapse и релакс хаотично — каждый раз проекция «отъезжает»,
набегает ошибка. Оригинал ⚀ держит порядок: топологический проход → проекция → релакс → повтор.
**Проверка:** число итераций до сходимости < 50; если расходится — нарушён порядок или нет демпфирования.

### 5.4. Релакс по длине ребра, а не чистый Лаплас
⬛ `grelaxalgo-LaplaceWithEdgLen`.
**Наша ошибка:** обычный umbrella-Лаплас → меш сжимается (shrinkage). Вес `1/length` противостоит этому;
также нужен компенсирующий вес `shape_preservation`.
**Проверка:** bbox после 100 итераций релакса — изменение < 0.5%.

## 6. Численная часть

### 6.1. Разреженная система без правильного порядка перестановки — медленно и плохо
⬛ В `ChSolver.dll`: CHOLMOD + **AMD/CAMD/COLAMD** (явно перечислены в licenses/ReadMe.txt).
**Наша ошибка:** решать разреженную систему «как есть» — заполняемость L взрывается,
факторизация O(n²) вместо O(n^1.5) и численно нестабильно.
**Проверка:** сравнить время factorize с/без AMD на 100К вершинах — разрыв должен быть большим.

### 6.2. Численно точные предикаты
⬛ Triangle (Шевчук): `Number of 2D/3D orientation tests`, `incircle tests`, `adaptive precision`.
**Наша ошибка:** orientation/incircle на обычном `double` → на вырожденных треугольниках
противоположные решения → сломанная триангуляция, «шагает» между кадрами.
**Проверка:** почти-коллинеарные точки (area ~ 1e-14) — предикат обязан быть адаптивно точным.

### 6.3. ARAP/параметризация: нужны граничные условия
⬛ `bm-harmonic`, `bm-meanvalue`, `bm-shapepres`, `bm-circle`, `bm-square`, `bm-UVboundary`,
`arap-iter`, `arap-unwrap`.
**Наша ошибка:** «просто ARAP» без закрепления границы → вырождение (все вершины в одну точку).
Оригинал имеет **четыре разных граничных схемы** (круг/квад/UV-граница/форма границы)
и три разных весовых схемы гармоники — под разные задачи.
**Проверка:** параметризация на кольце/цилиндре — без вырождения, без инверсий граней.

## 7. Инженерные ловушки, которые видны по бинарнику

### 7.1. Внутренние коды ошибок — вперёд, не «throw and pray»
⬛ `Remeshing error (hb)`, `Remeshing failed. (BadInput)`, `(OutOfMemory)`, `Error: Remeshing Failed.`
**Наша ошибка:** кидать исключение на середине стадии и оставлять полусобранный меш.
**Проверка:** после любого отказа входные данные не изменены, стейт чистый.

### 7.2. Потолки по памяти и итерациям — везде
⬛ `densify-max-vertex-count`, `densify-max-iter-count`, `AllocatorBase: requested size would cause
integer overflow`, `RoundUpToMultipleOf: integer overflow`.
**Наша ошибка:** рекурсивные/итеративные процессы без потолков → OOM или вечный цикл
на вырожденном входе (см. жалобы на QRemeshify: «ремеш может идти неограниченно долго»).
**Проверка:** каждый цикл имеет `max_iter` и бюджет памяти; превышение → контролируемый отказ.

### 7.3. Тайминг по стадиям — обязательный
⬛ `last algo total time = %.3f s`, `Algorithmic statistics:`.
**Наша ошибка:** «долго» без понимания, где. Без таймингов оптимизация невозможна.
**Проверка:** в логе каждого прогона — таблица stage → time; аномалия (>2× медианы) видна сразу.

### 7.4. Совместимость пресетов/параметров
⬛ Множество слагов вида `*-param` и устаревшие (`DoRetopoFromCmdLine_OLD`, `auto-retopo-zrem`).
**Наша ошибка:** переименовали параметр — старые пресеты пользователя перестали работать.
**Проверка:** алиасы старых имён + чтение неизвестных ключей без падения.

### 7.5. Чужие библиотеки — не тащить в ядро без нужды
⬛ В бинарнике: Qt (UI), FBX SDK, Crypto++ (лицензирование), libpng/zlib, CHOLMOD, Triangle.
**Наша ошибка:** связать ядро с Blender/Qt-типами → не тестируется без GUI, не переиспользуется.
**Проверка:** ядро собирается и проходит юнит-тесты в headless CI без Blender.

## 8. Сводный «минимальный набор сравнения» для своего пакета

Запускаем **свой** и **эталон** (QuadRemesher / QRemeshify) на одних и тех же моделях и сравниваем:

| # | Метрика | Порог для нас |
|---|---|---|
| 1 | Quad ratio | ≥ 95 % |
| 2 | Max deviation от оригинала | ≤ заданного (напр. 0.1% bbox) |
| 3 | Aspect ratio (95-й перц.) | ≤ 4.0 |
| 4 | Доля полисов valence≠4 | ≤ 5 % вне зон сингулярностей |
| 5 | Симметрия (mirror delta) | = 0 при включённой симметрии |
| 6 | Ступени плотности (stair) | визуально 0, численно — нет скачков >2× между соседними ячейками |
| 7 | Время (500К трис) | ≤ 15 с, без риска зависания |
| 8 | Детерминизм (2 прогона) | бит-в-бит |
| 9 | Отказ на битом входе | чистый `BadInput`, данные не тронуты |

**Формула сравнения на спорных моделях** (спираль, ткань, полисы, шум):
лучший результат — тот, где метрики 1–3 выполнены **без ручной подстройки** параметров.

## 9. Топ-10 ошибок, которые мы почти наверняка допустим (и как их поймать заранее)

1. **Поле на шуме** → нет денойза кривизны перед Propo. *Ловушка:* тест на меше со шумом.
2. **Полюса/сингулярности в плохих местах** → нет управления полюсами. *Ловушка:* сфера, голова.
3. **Разъезд симметрии** → симметрия только в конце. *Ловушка:* асимметричный шум + включённая симметрия.
4. **Ступени на шве плотности** → нет штрафа `penal-stair`. *Ловушка:* два размера сетки рядом.
5. **Съеденные feature-кривые** → релаксация поля не закрепляет кривые. *Ловушка:* контур на плоскости.
6. **Взрыв числа полигонов** → нет `densify-max-*`. *Ловушка:* узкая кривая на мелкой сетке.
7. **Зависание на вырожденном входе** → нет потолков итераций. *Ловушка:* нулевые треугольники, 1 полигон.
8. **Хуже, чем QRemeshify на спиралях** → сборка квадов не итерируется по несовместимостям. *Ловушка:* именно эта модель.
9. **«Примерно N квадов»** → нет точного распределения по патчам. *Ловушка:* target=5000.
10. **Медленно на 500К** → нет AMD-перестановки/потоков. *Ловушка:* бенч на 500К трис в CI.

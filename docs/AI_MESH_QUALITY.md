# Качество ремешинга AI-мешей

Изменения корректируют существующие этапы QRemesh. Новые сторонние зависимости не добавляются, ABI C API не меняется.

## Что изменено

- **Stage 5 — проекция внутри патча.** Узлы гармонической релаксации сначала проецируются на BVH текущего патча, а не на общую поверхность всей модели. Глобальный BVH используется только для ограниченного переноса точки на исходную поверхность, если расстояние мало и нормали согласованы. Это снижает вероятность перескока на соседнюю оболочку тонкой стенки или близко расположенную деталь. Число гармонических проходов по умолчанию уменьшено с 16 до 8; `QREMESH_HARMONIC_ITERS` сохраняет возможность переопределения.
- **Stage 6 — правильная классификация границ.** `original_bvh` строится после Stage 0, где исправление non-manifold-топологии может удалить грани и создать новые граничные рёбра. Раньше эти искусственные границы могли ошибочно приниматься за исходный открытый контур и оставаться незакрытыми. Теперь эталон открытого контура берётся из сырого входного меша. Для возврата старого поведения есть `QREMESH_HOLE_ORIGINPUT=0`.
- **Отверстия и pinch-границы.** По умолчанию используется направленный обход, который умеет разделять петли, соприкасающиеся в pinch-вершинах. Ориентация заплатки рассчитывается по рёбрам конкретной петли, а не по произвольному соседу вершины. Лимит закрываемой петли увеличен с 30 до 64 вершин. Настройки можно переопределить через `QREMESH_HOLE_PINCH=0` и `QREMESH_HOLE_LIMIT=<n>`.
- **Уважение открытых поверхностей.** Защита исходных открытых границ теперь включается только при `preserve_open_borders=true`. Оставляйте её включённой для листов, чаш и других намеренно открытых поверхностей. Для AI-модели, которая должна быть замкнутым телом, отключайте `Preserve Open Borders` в Blender или используйте `--fill-open-boundaries` в CLI.
- **Безопасное положение центра заплатки.** Центр крышки больше не безусловно притягивается к ближайшей точке всей исходной модели. Проекция выполняется только при расстоянии не более четверти квадрата целевого шага и согласованном направлении нормалей. Это снижает риск перескока на обратную сторону тонкой детали.
- **Более мягкая финальная релаксация.** Значение по умолчанию снижено с 20 до 6 итераций. Шаг уменьшен до `0.20`, ограничение смещения — до `0.35` длины кратчайшего ребра. Параметры доступны через `QREMESH_RELAX_ITERS`, `QREMESH_RELAX_STEP` (значения `(0, 0.4]`) и `QREMESH_RELAX_CAP` (значения `(0, 1]`).
- **Контроль раннего QEM-упрощения.** При входе свыше `proxy_tri_threshold` Stage 0 упрощает рабочую сетку до этого порога (по умолчанию 300 000 треугольников). Рёбра с флагами sharp/seam и границы защищены, но мелкий рельеф не гарантированно сохраняется. Для очень детализированных входов поднимайте `proxy_tri_threshold` в C API или `QREMESH_PROXY_THRESHOLD` (например, до 500 000–1 000 000) и проверяйте расход памяти/время. Не снижайте порог, если важны мелкие детали. Также увеличивайте `target_quad_count`, когда целевая сетка слишком грубая: сглаживание не может восстановить детали, для которых не выделено полигонов.

## Пример запуска CLI

```bash
QREMESH_HOLE_ORIGINPUT=1 \
QREMESH_HOLE_PINCH=1 \
QREMESH_HOLE_LIMIT=64 \
QREMESH_HARMONIC_ITERS=8 \
QREMESH_RELAX_ITERS=6 \
QREMESH_RELAX_STEP=0.20 \
QREMESH_RELAX_CAP=0.35 \
./build/qremesh_cli input.obj -o output.obj --quality=safe --fill-open-boundaries
```

`--fill-open-boundaries` используйте только для объектов, которые должны быть закрытыми телами. Для намеренно открытых оболочек, чаш и листов не включайте этот флаг. В Blender эквивалент — выключить `Preserve Open Borders`.

## Регрессионная проверка

Сравнивайте результаты с базовым коммитом на одинаковых моделях:

1. **Замкнутая модель с non-manifold-ответвлением:** число граничных рёбер не должно расти; искусственно открытые петли до 64 вершин должны закрываться.
2. **Открытая чаша или лист:** исходный длинный открытый контур должен сохраниться; не включайте `--fill-open-boundaries`.
3. **Две близкие параллельные оболочки / тонкая стенка:** узлы Stage 5 не должны перескакивать на противоположную поверхность.
4. **Мелкий рельеф, надписи, канавки, болты и острые гребни:** сравните силуэт, RMS и Hausdorff deviation и проверьте одинаковые крупные планы до/после.
5. **Pinch / figure-eight граница:** направленный обход должен разделять простые подпетли; у каждого ребра должно быть не более двух инцидентных граней.

Минимально фиксируйте `Boundary edges`, `Non-manifold edges`, `Connected components`, `RMS Deviation`, `Hausdorff Max`, `Min Scaled Jacobian` и общее время. Не принимайте визуально более гладкий результат, если ухудшились граничные или Hausdorff-метрики. CLI выводит эти показатели, но пока не проверяет проектные пороги автоматически.
